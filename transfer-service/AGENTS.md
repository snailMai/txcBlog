# Snail Transfer

自用的 Windows／安卓文字、图片和文件传输工具。服务可运行在电脑或服务器，客户端通过同一 HTTPS 地址访问；历史和原文件由服务端持久保存。

## 目录与边界

- `transfer/`：Flask 应用、SQLite 存储与文件传输逻辑；`static/`、`templates/` 为无构建前端。
- `tests/`：使用隔离数据目录验证鉴权、传输完整性、并发、配额和备份恢复。
- `scripts/`：初始化、运行、备份和恢复入口；`deploy/`：部署说明和可审查的配置模板。
- `data/`：默认运行数据目录，包含凭据、数据库、原文件、缩略图和未完成上传，禁止提交。
- `.tmp/`：本次开发的测试数据和预览产物；不得成为正式运行依赖。

## 工程约束

- 单账号、单服务进程、多线程；使用进程文件锁防止多个实例同时写同一数据目录。SQLite 事务与应用写锁协调配额、分片和消息提交。
- 原文件只用服务生成的 UUID 存储；原始文件名仅作展示和下载名。所有附件、缩略图和历史接口必须鉴权。
- 发送成功必须代表文件完成校验并已持久保存。消息提交使用客户端幂等键；半成品不得出现在历史。
- 文件读取、分片校验、请求及响应解析必须有明确阶段和超时，可取消；取消／超时保留已确认分片。分片重试前核对服务端状态，记录提交结果未知时沿用原幂等键，不能将超时当作未保存。
- 文件在服务端不可变；本地下载副本不参与文件夹同步。默认保留原文和原文件，禁止隐式删除历史以腾出空间。
- 批量删除只接受用户明确勾选的记录 ID；全选仅覆盖当前已加载列表，切换搜索／类型清空勾选。确认时冻结目标集合，服务端重试不得扩大删除范围；只用隔离合成记录测试删除，不试删生产历史。
- 记录采用紧凑卡片，来源／状态／时间集中展示，操作位于卡片顶部右侧：复制文字、各附件的复制图片／下载、最后删除记录。图片下载统一显示「下载」，多附件明确对应文件；窄屏允许操作区在正文上方换行，不隐藏原有操作或撑出横向滚动。
- 发送输入框按文字及实际换行自动伸缩，空白从一行起（占位文字按宽度自然换行）、最多约 8 行后内部滚动；程序填入、删空和成功发送后同步尺寸，失败保留内容。底部不保留常驻提示栏，仅在容量达到 90% 时显示容量警告。
- 同源请求、CSRF 防护和安全 Cookie 为必需项；外部部署必须 HTTPS，禁止信任客户端提供的转发身份头。
- 访问密码允许 10～256 个字符，不强制字符组合；网页改密必须校验旧密码，并在同一事务中更新哈希、撤销全部会话。改密失败不得改变密码或会话，不记录密码正文，不改历史与附件。
- 中文文案经前端确定性格式化处理；动态用户内容保持原文，使用安全文本渲染。
- 备份包含数据库一致快照、原文件与清单；恢复仅允许到全新目录，并校验附件哈希。禁止覆盖运行数据。

## 工作流与验证

正式源码随 txcBlog 仓库维护，路径为 `/Users/macminimai/ai/project/personal-tools/back-end/blog/transfer-service`，不并入 Maven 构建。原 `/Users/macminimai/ai/project/snail-transfer` 仅保留原虚拟环境与历史临时证据，生产发布包、真实数据和启动项不随源码移动。迁移后本机可使用该原虚拟环境的 Python；新环境按 README 创建目录内 `.venv/`。

当前宿主已确定为 Mac mini，入口复用 personal-tools 的 `https://tools.20242233.xyz/Transfer`。传输服务保留独立实现，以 `--prefix /transfer` 挂载，站内同源嵌入 `/transfer/?embedded=1`；独立运行不带前缀的使用方式仍兼容。

挂载模式中 Cookie、静态文件、API、manifest、分享目标和 Service Worker 必须局限于挂载路径，不能接管站点根路径；只允许同源嵌入，独立根路径模式继续禁止嵌入。运行数据不与 todoist Markdown 混用，不改共享隧道或生产服务，未授权时不初始化真实密码。

先读 `ROADMAP.md` 判断状态，运行和数据操作以 `README.md` 为准。部署参考 `deploy/README.md`。

按用户持续授权，修改／修复通过必要验证后直接定点部署传输组件，遵循上级 AGENTS.md 的发布范围及回退要求；不据此提交或推送 Git，若当次要求只读或暂缓则停止在相应边界。
